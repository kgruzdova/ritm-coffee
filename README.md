# РИТМ — кофейня в твоём ритме

Самостоятельный концепт кофейни, вдохновлённый композицией и последовательностью приложенных кадров. Все фотографии созданы специально для проекта. Исходные скриншоты не используются на странице.

## Запуск

```sh
npm install
npm run dev
```

Открыть http://127.0.0.1:5173. Для проверки готовой сборки:

```sh
npm run build
npm run preview
```

Preview доступен на http://127.0.0.1:4173. Production-файлы находятся в `dist/`.

На компьютере, где создавался проект, системный `npm.ps1` ссылается на отсутствующий файл. Исправный npm можно вызвать напрямую, не меняя настройки компьютера:

```powershell
node 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' run dev
```

## Стек и компоненты

React + Vite, GSAP + ScrollTrigger, Lenis, SplitType. Three.js и WebGL не используются.

- `App`: состояние загрузки, меню, списка напитков и отложенной навигации.
- `Preloader`: счётчик 000—100, SVG-стакан с заполнением снизу, уход экрана вверх. Ожидает декодирование главной фотографии и загрузку шрифтов; имеет кнопку пропуска и ограничение ожидания.
- `Navigation`: плавающая фиксированная шапка с отступами от краёв окна и скруглением 24 px (20 px на телефоне), из тёплого тонированного матового стекла: полупрозрачный градиент, backdrop blur 24 px, тонкая светлая граница и мягкая тень. Плотность тонировки сохраняет читаемость на светлых секциях; браузеры без backdrop-filter используют сплошной фон. Отступ прокрутки учитывает верхний зазор и высоту шапки. Мобильное меню сохраняет управление фокусом.
- `Hero`: текст, чек, фотография и предметная подпись. Высота секции зависит от содержимого и высоты окна; текст не обрезается на низких desktop. В мобильной композиции контакты идут под кнопкой, плашка остаётся над крышкой, а стакан заходит под следующую светлую секцию и обрезается её границей. Надпись о заботе напечатана внизу чека. Отдельные обёртки для вступления, scroll-анимации и лёгкой реакции на мышь. Стакан и чек смещаются в противоположных направлениях и мягко возвращаются при уходе курсора.
- `DrinkTicker`: циклическая смена авторского латте, эспрессо и капучино с соответствующими ценами и описаниями. Каждая подпись полностью показана 7 секунд, затем сменяется через перекрывающийся crossfade длительностью 0.6 секунды. Первый отсчёт начинается после вступления Hero; плашка остаётся заполненной при запуске и переходах. Анимация приостанавливается вне экрана и в скрытой вкладке; reduced motion оставляет первую подпись неподвижной.
- `Products`: восемь карточек в одном горизонтальном ряду и добавление в список. На desktop видны четыре карточки, на телефоне — одна с краем следующей. Нативная прокрутка, стрелки без autoplay, свайп/трекпад и клавиши Left/Right/Home/End сохраняют обычное движение всей секции по странице. Неподвижная внешняя обёртка отслеживает курсор, поверхность наклоняется до 4° по Y и 3° по X, изображение смещается до 5/4 px внутри неё. Масштаб остаётся 1, название и цена закреплены на поверхности. GSAP quickTo сглаживает наведение за 0.25 s и возврат за 0.4 s; reduced motion и отсутствие точного указателя отключают эффект.
- `CoffeeGuide`: компактный блок после карточек, перед циферблатом. Пять вкладок переключают предоставленные пользователем фотографии состава, название, характер вкуса и ингредиенты. Изображения декодируются перед сменой, быстрые запросы выбирают последний напиток. GSAP crossfade сохраняет один размер кадра; reduced motion отключает анимацию. Управление стрелками, Home/End, роли tab/tabpanel. На телефоне фото стоит выше текста. Кнопка возвращает к существующему меню без создания новых позиций заказа.
- `CoffeeSteam`: шесть мягких полупрозрачных SVG-струек над двумя чашками на lifestyle-фото. У всех разные длительности и фазы CSS-анимации. SVG использует тот же cover crop, что и фотография, и наследует её параллакс. Анимации приостановлены за пределами экрана и в скрытой вкладке, компонент отсутствует при reduced motion.
- `ClockSection`: ровный SVG-циферблат полностью помещается в кадр и не вращается. Секция прокручивается вместе со страницей без закрепления, стакан наклоняется от 0° до +25°. Три адреса переключаются мышью и клавиатурой.
- `DarkPromo`: отдельные соседние тёмная секция и lifestyle-секция в обычном потоке. В тёмной секции стакан сохраняет положение и масштаб, наклонён на 9° и обрезается её overflow. Положение учитывает альфа-поля изображения и центр крышки. Единственная timeline `dark-parallax` управляет фоном, зёрнами и masked reveal заголовка с прямым scrub. В наличии один плоский ракурс; полноценный поворот печати требует дополнительных кадров, описанных в `docs/cup-turn-assets.md`.
- `RevealTitle`: SplitType разбивает явно заданные строки; каждая строка раскрывается внутри маски через `yPercent`, без fade основных заголовков.
- `OrderDialog`: нативный dialog с количеством товаров, выбором кофейни и скачиванием текстового списка для бариста. Отправка заказов на сервер и онлайн-оплата не подключены.
- `Footer`: навигация, адреса и возврат наверх.

Меню, цены и демонстрационные адреса редактируются в `src/data/menu.js`. Заглушки «Телеграм» и «ВКонтакте» в Hero настраиваются в `src/data/socials.js`: замените `href: null` официальным URL, чтобы включить переход. Пока адресов нет, заглушки не прокручивают страницу и не открывают посторонние профили. Палитра, размеры и адаптив — в `src/styles.css`. Бренд и адреса являются частью концепта, а не данными действующей сети.

## Как восстановлено движение по кадрам

Последовательность 01 соответствует самостоятельному экрану загрузки: число увеличивается, заполнение SVG привязано к тому же значению; после готовности весь экран поднимается на 101%.

02—03 показывают вход предметов снизу и последующее расхождение слоёв. Вступление: чек `y: 500 → 0`, rotation `8 → 0`; стакан `y: 400 → 0`, rotation `−5 → 0`. Небольшой финальный наклон задаётся внешней обёрткой. При прокрутке чек проходит −60 px, стакан −120 px, текст −40 px; фон увеличивается до 1.03. Светлая секция имеет больший z-index и перекрывает нижний край Hero.

04—05 сохраняют сетку карточек в обычном потоке страницы без дополнительного движения по Y, pin или каскадного появления. У каждой карточки своя поверхность с перспективой 900 px и независимые hover tweens. Координаты берутся относительно неподвижной обёртки, в том числе при прокрутке с неподвижным курсором; размеры сетки и промежутки не меняются.

Секция 06—07 доработана: циферблат не анимируется, число 12 всегда сверху, круг целиком помещается в доступную высоту под шапкой. При обычной прокрутке секции напиток наклоняется `0 → 25°`, слегка поднимается и меняет масштаб `0.94 → 1.02`. Размеры круга учитывают и ширину, и высоту экрана.

Переход 08—09 следует обычной прокрутке страницы: светлая секция выходит вверх, тёмная входит снизу. На широком desktop центр крышки стакана находится на 32% ширины секции и 53svh от её верха, видимая ширина — 31vw. Размер прозрачного холста пересчитан по измеренной альфа-границе. Стакан сохраняет фиксированный наклон 9°; дополнительного подъёма по Y, смещения по X и изменения масштаба нет. Фон и зёрна остаются позади, masked reveal заголовка управляется той же scrub timeline. Следующая lifestyle-секция начинается строго после тёмной, без наложения стакана. Для поворота печати нужны согласованные прозрачные ракурсы −30°…+25°; один текущий PNG не вращается по rotationY. Требования к кадрам и контрольные progress описаны в `docs/cup-turn-assets.md`.

Секция часов прокручивается без pinning и дополнительной дистанции. Наклон напитка связан с проходом секции через окно. Hero и часы используют `scrub: 1`, тёмный переход — `scrub: true`, чтобы не было догоняющего tween после остановки. При reduced motion scroll-анимации отключены.

## Прокрутка, производительность и доступность

Lenis работает от `gsap.ticker`, время передаётся в миллисекундах. Его событие `scroll` вызывает `ScrollTrigger.update`; отдельного конкурирующего RAF-цикла нет. При размонтировании удаляются ticker callback, обработчик scroll и экземпляр Lenis. Секции используют `gsap.context().revert()`, SplitType возвращает исходную разметку, все обработчики и таймеры очищаются.

При `prefers-reduced-motion: reduce` отключены Lenis, scroll timelines, параллакс, reveal и задержка загрузочной анимации. Настройка отслеживается в реальном времени. На телефонах амплитуда Hero уменьшается до 30%, тёмного параллакса до 25%, перемещения стакана часов уменьшаются; touch-прокрутка остаётся нативной.

Фотографии сохранены локально в AVIF и WebP, с вариантами ширины 480 и 960 px; lifestyle-фото — 480 и 1440 px. Используются `picture`, `srcset`, `sizes` и lazy loading. Главная фотография загружается с высоким приоритетом и preload. Шрифты Golos Text и Caveat хранятся локально; лицензии SIL OFL находятся рядом с ними.

## Проверка в браузере

```sh
npm run qa
```

Нужен установленный Google Chrome и запущенный dev-сервер. Для проверки production-сборки:

```powershell
$env:QA_URL = 'http://127.0.0.1:4173'
npm run qa
```

Playwright проверяет 1440×900, 834×1112, 390×844 и 320×700 с reduced motion. Проверки: консоль/HTTP-ошибки, загрузка шрифтов и фотографий, горизонтальное переполнение, Hero/Clock/Dark scroll transforms, мобильная навигация, выбор адреса клавиатурой, количество товаров и содержимое скачанного списка. Скриншоты и JSON-отчёт сохраняются в `artifacts/`.

Дополнительная проверка `npm run qa:lifecycle` работает с dev-сервером на 5173: три переключения reduced motion должны удалять все ScrollTrigger и Lenis, затем восстанавливать ровно исходное количество. Смена ширины экрана не повторяет Hero intro. Проверяется также нижняя точка роста жидкости в прелоадере.

`npm run qa:ticker` проверяет production preview на 4173: снимает состояние плашки каждый кадр в течение полного цикла на desktop и mobile, включая первый показ и переход обратно к латте. Проверяет отсутствие пустых кадров, длительность первого показа и новый текст «Авторский латте».

`npm run qa:clock` проверяет полный циферблат без вращения, наклон напитка от 0° до +25° и обычную прокрутку без pin spacer на шести размерах окна, включая низкие desktop/tablet. Проверяет возврат через «Адреса» и отключение анимации при reduced motion.

`npm run qa:transition` проверяет dev-сервер на 5173: измеренное размещение стакана с учётом прозрачности, постоянство положения и масштаба внутри секции, естественное движение секций, обрезание, единственный прямой scrub, остановку и обратную прокрутку. Проверяет пять размеров экрана, включая низкий desktop и small mobile.

`npm run qa:products` проверяет центр и края карточек, внутренний параллакс, плавный возврат, независимость соседей, прокрутку с курсором над карточкой и сохранение геометрии сетки. Проверяет desktop/tablet, сенсорный экран и переключение reduced motion; скриншоты и результаты — в `artifacts/`.

`npm run qa:coffee-guide` проверяет пять напитков, отсутствие пустых кадров во время crossfade, быстрые переключения, управление стрелками/Home/End, стабильную высоту панели и переход к меню под плавающей шапкой. Проверяет пять ширин, мобильное расположение и reduced motion. Фотографии состава взяты из предоставленных пользователем `separate-keyframes/{espresso,americano,kapuchino,latte,raf}.png` и экспортированы в `coffee-guide-*` AVIF/WebP; исходники сохранены.

Скрипт `scripts/optimize-assets.cjs` повторно кодирует исходные PNG без изменений оригиналов. Путь к папке оригиналов передаётся аргументом. Готовые изображения уже включены в `public/assets/`; повторная оптимизация для запуска не нужна.

Промпты и сведения о созданных изображениях: `docs/asset-prompts.md`.

## Секции и проверка адаптации

Нумерация последовательная: 01 — первый экран; 02 — меню; 03 — кофе по слоям; 04 — время для кофе; 05 — в нашем ритме; 06 — маленькие паузы; 07 — встретимся за кофе. Номера товаров и адресов остаются отдельными последовательностями.

`npm run qa:responsive` проверяет 13 размеров от 320 до 1920 px, включая низкие окна: композицию Hero, обрезание стакана, доступность кнопок, нумерацию, один ряд карусели, стабильную высоту, цены, выбор новых товаров, пустой список, обязательный выбор кофейни, ошибки скачивания и восстановление. `npm run qa:failure` проверяет нативный свайп, горизонтальный трекпад и отказ загрузки фотографии без исчезновения текущего изображения.

В существующем списке для бариста кофейня выбрана по умолчанию; select имеет required. Пустой список нельзя скачать, статус объясняет следующий шаг. Ошибка подготовки файла показывается через alert. Статус успешной подготовки не обещает завершённое сохранение на устройстве. Личные данные не запрашиваются.

## GitHub Pages

Сайт: https://kgruzdova.github.io/ritm-coffee/

Репозиторий: https://github.com/kgruzdova/ritm-coffee

Workflow `.github/workflows/pages.yml` собирает проект через `npm ci` и `npm run build`, затем публикует `dist` при каждом push в `main`. В настройках Pages выбран источник GitHub Actions. Production base задаётся переменной `VITE_BASE_PATH=/ritm-coffee/`; локальный dev продолжает работать по корневому адресу. Публичные фотографии и шрифты входят в репозиторий; исходные PNG, видео и референсы сохранены локально и исключены из публикации.

`npm run qa:pages` проверяет сборку с base `/ritm-coffee/`. Для проверки опубликованного сайта установите `QA_URL=https://kgruzdova.github.io/ritm-coffee/`.
